# Running ARES

This page describes the complete workflow for running an ARES simulation: preparing the case directory, defining the input, launching the solver, and inspecting the output.

A case is driven by:

- `input.ini` — the main INI file. It contains both the **ARES solver** sections (`[ARES-*]`) and the **ATLAS pre-processing** sections (`[GRIB-*]`, `[GPB-*]`, `[ICB-*]`, `[BCB-*]`).
- `INPUT/` — the supporting data files generated by ATLAS from those pre-processing sections: the real-fluid table (`phase.txt`, `thermo.dat`), the initial condition (`ic.*`), and the boundary conditions (`bc.txt`).

!!! tip
    The files in `INPUT/` are normally built by **ATLAS**. ATLAS is powerful but not strictly required: the files can be created manually or by custom scripts as long as they follow the expected format (see [Initial Conditions](initial-conditions.md) and [Boundary Conditions](boundary-conditions.md)).

---

## Simulation Workflow

A typical ARES run follows four phases:

1. **Setup** — define the mesh, real-fluid table, initial and boundary conditions (the `[GRIB/GPB/ICB/BCB]` blocks of `input.ini`).
2. **Preprocess** — ATLAS generates the `INPUT/` data from those blocks.
3. **Solve** — ARES advances the solution in time (explicit integration).
4. **Postprocess** — solution fields, wall data, probes, and the residual history are written to `OUTPUT/`.

---

## Case Directory Structure

Every ARES case follows a standard layout:

```
my_case/
├── input.ini                 ← case configuration (ARES + ATLAS blocks)
├── ARES.sh                   ← convenience run script
├── INPUT/
│   ├── phase.txt             ← real-fluid table descriptor
│   ├── thermo.dat            ← tabulated thermodynamic / transport data
│   ├── ic.*                  ← initial condition (mesh + flow field)
│   └── bc.txt                ← face-by-face boundary-condition table
└── OUTPUT/                   ← created at runtime
    ├── field.*               ← solution fields (when sol-overwrite = true)
    ├── field1.*, field2.*    ← solution snapshots (when sol-overwrite = false)
    ├── wall.*                ← wall quantities (viscous cases only)
    ├── diagnostic.*          ← cell residuals and local time step (steady runs only)
    ├── field-level<N>.*      ← solution on multigrid level N > 1
    ├── field-prolongated.*   ← level-N solution prolongated to the finest grid
    ├── residual-history.dat  ← residual norm vs. iteration
    └── <probe>.txt           ← time-history at probe locations
```

!!! warning
    ARES reads the grid geometry directly from the initial-condition file (the `x`, `y`, `z` node coordinates). There is no separate mesh file consumed by the solver.

!!! note "Mesh type"
    ARES takes the type of the mesh from the nodes of every block. The mesh is 3-D if a block has more than one cell
    in $k$, 2-D if not and a block has more than one cell in $j$, 1-D otherwise. A 2-D mesh is an axisymmetric wedge
    when, in every block, the $k = 1$ node plane is the $k = 0$ plane turned about the $x$ axis by the same angle ($x$
    and $r = \sqrt{y^2+z^2}$ kept, nodes on the axis included); it is plane when no block is so turned, and a mesh
    with blocks of both kinds stops the run. In 3-D, type `200` on faces 5 and 6 closes a sector: the last $k$ node
    plane of the block is the first one turned about the $x$ axis by the same angle in every such block, or translated
    (a periodicity with no rotation); otherwise the run stops. A block closed on itself over a full turn about $x$,
    its last $k$ node plane on the first one, is translated by zero: the periodicity by the identity. Every node is
    checked against the move of the nodes per cell in $k$, measured along the $k$ lines (for every node of the $k = 0$
    plane the sum of its moves across the cells of its $k$ line, the largest over the plane, divided by the number of
    cells in $k$; the thickness of a 2-D block). A block is turned when its nodes match the turn
    to within 1 % of that move and better than a translation, translated when they match a translation to within
    1 % of it and better than a turn, or when the angle is null (a turn by the null angle is the translation by
    zero), and the angles of the blocks agree to 1 %. So the round-off of the coordinates in the file has to stay below
    1 % of a cell in $k$, and a plane slab far from the $x$ axis, which a small turn nearly fits, stays plane. In a
    wedge whose two planes lie symmetric about $z = 0$ ($y$ the same in both), four significant digits are enough at
    any angle, three are not in general. A 2-D block nearer a turn than a translation, or nearer
    a translation than a turn, but not to 1 %, stops the run: write its coordinates with more digits, or make its $k$
    planes parallel for a plane mesh. So does a 2-D block whose node $(0,1)$ (or the node farthest from the axis,
    when that one lies on it) keeps its azimuth while its $k = 1$ node plane is not the $k = 0$ plane translated to
    1 %: $k$ planes that touch or cross, or a $k = 1$ plane scaled radially about the axis. The set-up summary
    names the type, as `Mesh type`: 1-D, 2-D plane, 2-D axisymmetric wedge with its angle in degrees, 3-D, or 3-D
    with the angle of its sectors. The periodic images of the wall in the wall distance of the turbulence models
    follow the same 1 % rule ([Turbulence](../theory/turbulence.md#wall-distance)). The cells are checked at set-up
    too ([Spatial Discretization](../theory/numerics.md#checks-of-the-cells-at-setup)).

## Running the Solver

The bundled `ARES.sh` script wraps the common tasks:

```bash
./ARES.sh compile          # build a local bin/ARES from the master build
./ARES.sh solve            # run in the foreground
./ARES.sh solve -p 4       # run with 4 OpenMP threads
./ARES.sh solve -m 2 -p 4  # run with 2 MPI processes × 4 OpenMP threads (hybrid)
./ARES.sh solve -b -p 4    # run in background (stdout → logfile, PID → .ID)
./ARES.sh kill             # kill a background run via the stored PID
```

`ARES.sh solve` sets the environment ARES needs and launches the binary:

```bash
ulimit -s unlimited        # ARES uses a large stack
export KMP_STACKSIZE=100M  # Intel/OpenMP stack per thread
export OMP_NUM_THREADS=4
./bin/ARES
```

!!! warning "Stack size"
    ARES allocates sizeable automatic arrays. Always run `ulimit -s unlimited` (and set `KMP_STACKSIZE` for Intel/OpenMP) before launching, or the solver may crash with a segmentation fault on the first flux evaluation. `ARES.sh` does this for you.

## Logging and Diagnostics

ARES prints diagnostics to the console (or to `logfile` when run with `-b`). The output begins with a banner, then a **Loading** block, a **Set-up** summary, the **Physical model** and **Numerical scheme** descriptions, and finally the iteration log.

```

 =========================================================================================
 Loading
 =========================================================================================
   Thermodynamics                 OK
   Transport                      OK
   Thermo inversion               OK
   Input file                     OK
   Initial conditions             OK
   Boundary conditions            OK
 =========================================================================================

 =========================================================================================

 =========================================================================================
 Domain
   Blocks                         1
   Cells                          13056
   Boundary faces                 26576

 Boundary conditions
   Viscous wall                   112
   Inflow/outflow                 192
   Symmetry                       160
 =========================================================================================

 =========================================================================================

 =========================================================================================

   Equations                      Navier-Stokes
   Viscous model                  Turbulent, SST
   Equation of state              Real
   Thermodynamics                 Real fluid

ARES | Iter =     1000 | Global iter =   501000 | Pressure residual = 0.264793E-04
ARES | Iter =     2000 | Global iter =   502000 | Pressure residual = 0.262362E-04
ARES | Iter =     3000 | Global iter =   503000 | Pressure residual = 0.259158E-04
```

!!! tip "Loading checks"
    A clean `Loading … OK` block means the input files were read successfully. If something is missing or malformed, ARES prints an error and exits.

!!! note "Exit code"
    A run that ARES stops on an error, at loading, at set-up or because the solution diverges («Integration failed at
    b, i, j, k», then «NaN, infinity or p<0 detected»), ends with a non-zero exit code: 1 where ARES ends with `stop 1`
    or `error stop 1`, otherwise the one the MPI launcher gives for `MPI_ABORT` with error code 1. With MPI, an error
    that every rank finds (a line of `bc.txt`, a value of the initial condition that is not finite), an initial condition
    that cannot be read (also when one rank alone finds it) and an error that rank 0 finds at set-up or when it reads
    `input.ini` again stop every rank together: each rank writes its message, the ranks finalize MPI and end with exit
    code 1. A `stop` outside these collective stops, a divergence for instance, ends its own rank only, and the MPI
    launcher ends the run with a code of its own (255 with the `mpiexec` of Intel MPI 2021.12). A divergence is caught on
    any value that is not finite or on a negative pressure. The errors of each input are in its page
    ([Input File](input.md), [Boundary Conditions](boundary-conditions.md)).

    Known limit: errors raised inside the ORION library, which reads and writes the solution files, end with code 0,
    because ORION stops with `STOP` (for example a binary Tecplot file, `ic-format = tecplot binary`, in a build without
    TecIO: «You can not read in binary format without compiling against TecIO»). Check the end of the log, not only the
    exit code, when a run reads or writes binary files.

!!! note "Which residual?"
    For real-fluid / low-Mach runs ARES monitors the **pressure** residual (the natural convergence indicator when the primitive set is $(p, \mathbf{u}, h)$ and the pseudo-time derivative is preconditioned). `Global iter` is the cumulative iteration count across restarts; `Iter` is the count within the current run.

## Output

After a run, the `OUTPUT/` directory contains:

| File | Description |
|------|-------------|
| `field.*` | Solution fields ($p$, $u$, $v$, $w$, $T$, $\rho$, $h$, …) |
| `residual-history.dat` | Iteration-by-iteration residual norms |
| `wall.*` | Wall quantities (skin friction, heat flux) — viscous cases only |
| `diagnostic.*` | Cell residuals of every transported variable and the local time step `dt` — steady runs only |
| `<probe>.txt` | Time-history at the probe named `<probe>` |

### Multigrid output

With `levels > 1` in `[ARES-Multigrid]` the run starts on the coarsest level, and the files above belong to the finest one (level 1). While a coarse level $N$ is running, each solution output (`sol-diter`, `sol-dtime`, and the switch to the next finer level) writes:

| File | Description |
|------|-------------|
| `field-level<N>.*` | Solution on the grid of level $N$ |
| `wall-level<N>.*` | Wall quantities of level $N$, from its own boundary records and metrics — viscous cases only |
| `field-prolongated.*` | The level-$N$ solution prolongated to the finest grid |
| `wall-prolongated.*` | Wall quantities of the prolongated solution — viscous cases only |

Every file carries the time of its iteration (minus the global iteration count in a steady run). `prolongated-diter` in `[ARES-Multigrid]` spaces the prolongated files: with 0, the default, they are written with every field write of a coarse level; otherwise only once that many iterations of the level have passed since the last ones. The switch to the next finer level always writes them.

If the run ends on a coarse level (a threshold of `[ARES-Parameters]` is reached before level 1), the final files carry the level as well, `field-level<N>.*`, `wall-level<N>.*` and `diagnostic-level<N>.*`, and do not overwrite those of the finest level.

### I/O formats

Controlled by `sol-format` in `[ARES-IO]`:

| Value | Format |
|-------|--------|
| `tecplot ascii` | Tecplot ASCII (`.tec`) — default |
| `tecplot binary` | Tecplot binary (`.szplt`) — requires TecIO |
| `vtk ascii` | VTK ASCII (`.vts`) |
| `vtk raw` | VTK multi-block (`.vtm`) with its `.vts` block files in `OUTPUT/vtk/`, raw binary data appended to each file |

### Output variables

By default ARES writes primitive variables ($p$, $u$, $v$, $w$, $T$). Extra groups are enabled via `sol-variables` in `[ARES-IO]`:

- `thermo` — speed of sound, $\gamma$, gas constant, density
- `transport` — laminar viscosity $\mu_\ell$ (`mil`), conductivity $k_\ell$ (`kl`) and, with a turbulence model, the eddy viscosity $\mu_t$ (`mut`)

Wall output is controlled by `wall-variables`: $y^+$ is always written first; `mech` adds the wall shear components and pressure (`tauX tauY tauZ pw`), `thermal` adds wall temperature and heat flux (`Tw qw`). The sand-grain roughness of the wall cell (`hs`) is always written as the last wall variable (zero on smooth walls).

### Probes

Point-measurement time histories are configured with probe sections:

```ini
[ARES-Probes]
probe1 = exit

[exit]
variables = p T u
index-position = 50 33 1 1   ; i j k block
diter = 100
```

Each probe writes `OUTPUT/exit.txt` with columns for time/iteration and the requested variables. The accepted variables are `p u v w h T M` and, with a turbulence model, `mi_tilde`, the first transported turbulence variable (`rhoNuTilde`, `rhoK` or `ru'u'` in the solution files); an unknown name stops the run with the list. A probe given by `position` records the cell whose centre (the mean of its eight nodes) is the nearest to it. The rows with `diter` fall on the multiples of `diter` of the global iteration count; the time-based rows (`dtime`) on the multiples of `dtime`, from the first. Every row is passed to the file system when it is written. A new run replaces the probe file; a restart appends to it, and creates it when it is missing.

## Restart

Set `newrun = .false.` in `[ARES-Parameters]` to resume. ARES reads the initial state from the latest solution file in `OUTPUT/` instead of `INPUT/`, restoring the flow field, the physical time, the global iteration counter and, from a solution of a run of the same kind, the counters stored with it (output numbering, CFL ramp, multigrid level, the reference of `res-threshold`): see [Restart](initial-conditions.md#restart).

A steady run ends when its pressure residual has fallen by `res-threshold` from that of its first iteration (of each grid level), or at `iter-threshold`; `residual-history.dat` and the screen report the residual as it is. A time-accurate run ends at `time-threshold` or `iter-threshold`: `res-threshold` does not end it.
